# AI商品自动生成采集入库-标准开发文档

## 1. 文档信息
- 文档版本: `v1.6`
- 创建日期: `2026-03-04`
- 更新日期: `2026-03-19`
- 适用项目: `image-harvester/goods_excel`
- 目标系统: `jiujie_shop.jj_wangyi_goods`

## 2. 背景与目标
当前历史采集数据规模有限、颗粒度不足。目标是建设一套可持续运行的数据生产程序，按分类自动生成更细化的商品数据，并自动补齐图片后落库。

补充说明:
- 目标表 `jj_wangyi_goods` 中已存在一部分历史商品数据，后续新增生成任务必须尽量避开与库内历史数据重复或高度相似的商品。

核心目标:
- 支持按 `category_id + 关键词 + 数量` 生成商品。
- 使用千问模型生成结构化商品文案与价格。
- 使用图片接口抓取图片并映射主图/详情图。
- 落地到 MySQL 表 `jj_wangyi_goods`。
- 结果可控: 价格区间、地域覆盖、批次去重、库内去重、合规校验。

## 3. 范围与非范围
### 3.1 范围内
- AI 结构化商品数据生成。
- 图片接口抓取与商品图映射。
- 数据校验、重试、入库。
- 可选 Excel 导出与审稿模式。

### 3.2 范围外
- 前台商城 UI 改造。
- 商品上架审核工作流系统化开发。
- 支付、库存、订单模块。

## 6. 外部接口定义
### 6.1 千问接口
- URL: `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`
- 方法: `POST`
- 鉴权: `Authorization: Bearer ${QW_KEY}`
- 模型策略:
  - 默认主模型: `qwen-plus` (主生产模型，适用于绝大多数批量商品生成任务)
  - 回退/增强模型: `qwen-max` (复杂生成、失败修复、重点重写)

推荐使用原则:
- 本项目默认采用“`qwen-plus` 主跑 + `qwen-max` 补刀”的组合策略，不建议全量默认使用 `qwen-max`。
- `126 江苏特产`、`129 苏超纪念品` 默认优先使用 `qwen-plus`。
- `127 非遗` 默认使用 `qwen-plus`，高工艺、高客单、收藏级商品可切换 `qwen-max` 重写。
- `128 AI科技` 默认使用 `qwen-plus`，复杂方案型、高客单、交付范围难以表述清楚时可切换 `qwen-max`。
- 若 `qwen-plus` 输出连续出现 JSON 不稳、分类跑偏、标题质量弱、交付描述空泛等问题，可对失败候选切换 `qwen-max` 二次生成。
- 目标是让 `qwen-plus` 承担大部分吞吐和成本控制，`qwen-max` 仅处理高复杂度或高风险样本。

请求最小结构:
```json
{
  "model": "qwen-plus",
  "messages": [
    {"role": "system", "content": "系统提示词"},
    {"role": "user", "content": "任务提示词"}
  ],
  "temperature": 0.7
}
```

### 6.2 图片接口
- URL: `https://ptapi.jsss999.com/api/fetch/getImages?key=<关键词>`
- 方法: `GET`
- 返回示例:
```json
{
  "code": 1,
  "msg": "获取成功",
  "data": [
    "https://.../1.jpg",
    "https://.../2.jpg"
  ]
}
```

## 7. 数据契约与字段映射
### 7.1 AI输出契约(JSON数组)
为保证稳定解析，AI 端默认输出固定结构，不再采用宽松多态字段:
- `title` (string，必填，非空)
- `subtitle` (string，必填，非空)
- `price` (number，必填，正数，最多两位小数)
- `selling_points` (array[string]，必填，建议 `3 ~ 5` 条)
- `attrs` (object<string, string|number>，必填，默认不接受 array)
- `image_keywords` (array[string]，必填，建议 `1 ~ 3` 个非空关键词)

固定输出要求:
- `selling_points` 中不允许嵌套对象、数组或空字符串。
- `attrs` 的 value 应为标量，禁止再嵌套对象或数组。
- `image_keywords` 去重后至少保留 `1` 个有效词，不允许返回空数组。
- 除明确扩展字段外，默认禁止输出 schema 外字段，避免模型自由发散。

### 7.2 数据库映射
目标表: `jiujie_shop.jj_wangyi_goods`

| 目标字段 | 来源 | 规则 |
|---|---|---|
| `goods_name` | `title` | 必填，去重后写入 |
| `sub_title` | `subtitle` | 可为空 |
| `category_id` | 任务入参 | 必填 |
| `image` | 图片接口 `data[0]` | 必填，失败则重试/跳过 |
| `price` | `price` | 转 `decimal(10,2)` |
| `description` | 文案+详情图 | HTML 拼接 |
| `en_name` | 可选 | 可留空 |
| `create_time` | 系统时间 | 自动写入 |
| `update_time` | 系统时间 | 自动写入 |

### 7.3 description 拼接模板
```html
<div class="product-description">
  <p><strong>商品亮点</strong>：{{selling_points_text}}</p>
  <p><strong>规格属性</strong>：{{attrs_text}}</p>
</div>
<div class="product-detail">
  <p><img src="{{detail_img_1}}" /></p>
  <p><img src="{{detail_img_2}}" /></p>
  <p><img src="{{detail_img_3}}" /></p>
</div>
```

### 7.4 图片映射与降级规则
- 主图默认取首个通过校验的静态图片 URL，优先 `jpg/jpeg/png/webp`，默认不使用 `gif` 作为主图。
- 详情图按去重后的有效图片顺序取后续 `1 ~ 3` 张，数量不足时允许只写入已有张数，不得输出空 `img` 标签。
- 若仅有 `1` 张有效图片，则该图片作为主图，`description` 仅保留文案区块，可不拼接详情图区块。
- 若存在 `gif` 但没有静态图，`gif` 可作为详情图候选，不建议作为主图；连续重试后仍无静态图则判为图片失败。
- `128 AI科技` 优先使用项目内预置素材、静态效果图或与交付场景匹配的系统界面图；预置素材不足时再回退图片接口。
- `129 苏超纪念品` 应优先使用不含官方 logo、球员肖像、受保护视觉元素的通用场景图或自有风格图，避免侵权风险。
- 详情图 HTML 应根据实际可用图片数量动态拼接，禁止保留模板占位符或空链接。

## 8. Prompt工程标准
### 8.1 组装结构
- `system_prompt`: 全局角色与硬规则
- `category_profile`: 分类个性化规则
- `task_prompt`: 当前任务输入(关键词/数量/城市池)
- `output_schema`: 强制 JSON 字段定义
- `self_check_prompt`: 去重与合规自检
- `history_guard`: 库内历史标题摘要、禁用命名模式、重复提醒

Prompt工程目标:
- 稳定性优先于文案花样，先保证分类正确、价格正确、地域正确、结构正确，再追求表达丰富。
- 每轮建议按目标数量的 `1.2 ~ 1.5` 倍生成候选，再经程序校验、去重、补生成凑满最终数量。
- 同一任务尽量采用小批次生成，例如每批 `10 ~ 20` 条，降低大批量一次生成导致的质量漂移。
- 模型使用遵循“先 `qwen-plus`、后 `qwen-max`”原则，只有候选不达标或商品复杂度明显较高时才升级到 `qwen-max`。

### 8.2 system_prompt 约束
- 角色: 电商商品策划助手。
- 仅输出 JSON，禁止额外说明。
- 禁止输出 Markdown 代码块、标题、注释、解释文字、序号、前后缀说明。
- 禁止输出外链、联系方式、夸大承诺、违规内容。
- 强调江苏本地化语境。
- 标题、副标题、卖点、属性必须可直接用于电商后台，不得输出“示例”“参考”“可按需调整”等占位语。
- 禁止虚构知名品牌联名、官方授权、地理标志认证、疗效功能、保真承诺等无法验证的信息。
- 如任务已指定 `category_id`，则所有候选商品必须严格服从该分类定位，不得跨类生成。
- 如已提供历史标题黑名单或重复提醒，必须主动避开高相似命名。

### 8.3 分类个性化策略
- 126/129: 强约束价格，禁止夸高。
- 128: 服务型商品可高客单，但必须交付范围明确。
- 127: 工艺和材质信息必须可解释。

### 8.4 高质量输出约束
- `title` 建议 `14 ~ 28` 个中文字符，尽量包含“地域/品类/特色/场景”中的 `2~3` 个维度，不要堆砌泛营销词。
- `subtitle` 建议 `10 ~ 30` 个中文字符，必须补充产地特色、原料特色、工艺特色或适用场景，不得与标题简单重复。
- `selling_points` 建议输出 `3 ~ 5` 条，每条只表达一个清晰卖点，不要同义反复。
- `attrs` 优先输出对象结构，字段值应简洁明确，避免整段营销文案。
- `image_keywords` 必须服务于搜图，优先采用“城市/地域 + 商品名 + 细分词”的组合。
- 单批次商品在城市、细分类、价格带、礼赠场景上要有分散度，不能大量重复同一套路。
- 标题命名应接近真实电商商品，不要大量出现“高端臻选”“匠心尊享”“爆款热卖”等空泛套话。

### 8.5 江苏特产(126)专属提示词约束
定位要求:
- 以江苏本土食品、地方特产、农副加工品、伴手礼、节令礼盒为主。
- 商品应能被普通消费者一眼识别为“江苏相关特产”，不能伪装成全国通货。
- 低中客单为主，突出地方特色、送礼属性、节庆走访、企业伴手礼等场景。

优先生成维度:
- 地域维度: 南京、无锡、徐州、常州、苏州、南通、连云港、淮安、盐城、扬州、镇江、泰州、宿迁。
- 品类维度: 糕点点心、熟食卤味、米面粮油、茶饮冲调、地方零嘴、果干蜜饯、礼盒组合、节令食品。
- 表达维度: 产地、风味、原料、传统做法、送礼场景、节庆场景、净含量/规格。

禁止生成内容:
- 明显非江苏产地、非江苏文化来源的普通商品冒充江苏特产。
- 全国通用品牌零食、跨省常见快消品、纯进口食品、与江苏无明确关联的通货型商品。
- 与“特产”无关的数码、家居、文创、工艺摆件、服务类商品。
- 只有空泛营销词、看不出地域特色的标题，例如“臻选零食礼盒”“精品伴手礼”等。

126 标题和属性硬约束:
- 标题尽量体现 `江苏城市/地域 + 核心品类 + 特色/场景`。
- `subtitle` 必须写清地方风味、原料特点、适用场景中的至少一项。
- `attrs` 至少包含 `产地城市`、`规格`、`包装形式`、`适用场景`。
- `image_keywords` 至少包含一个江苏城市名或明确地域词。
- 常规价格应落在 `19.90 ~ 399.00`，高价礼盒必须体现礼盒构成、规格或送礼定位。

126 批次分布建议:
- 单批次尽量覆盖 `6` 个以上江苏城市。
- 礼盒类建议不超过本批次的 `40%`。
- `19.90 ~ 99.00` 为主力价格带，`100 ~ 399` 为补充价带，`399` 以上仅少量高端礼盒可出现。

### 8.6 非遗(127)专属提示词约束
定位要求:
- 以传统工艺、非遗技艺、地方手作、文化礼品、收藏赏玩型商品为主。
- 商品必须体现“工艺/材质/技法/文化出处”中的至少两项，不能只剩装饰用途。
- 适合礼赠、赏玩、茶空间、书房陈设、文化收藏等真实消费场景。

优先生成维度:
- 工艺维度: 宜兴紫砂、南京云锦、苏绣、竹编、木作、玉雕、金箔、香器香道、雕版、漆器、手工摆件。
- 表达维度: 材质、器型、工艺流派、手作程度、文化寓意、使用场景、礼赠收藏属性。
- 场景维度: 茶席、书房、家居陈设、节庆赠礼、商务礼赠、个人收藏。

禁止生成内容:
- 没有明确工艺出处的普通家居摆件、普通香薰、普通蜡烛、普通饰品冒充非遗。
- 虚构“大师监制”“馆藏同款”“官方认证”“孤品绝版”等无法证明的背书。
- 只有材质词、没有工艺说明的泛工艺品。
- 价格明显不匹配工艺复杂度和材质等级的夸张商品。

127 标题和属性硬约束:
- 标题尽量体现 `工艺/材质 + 器型/载体 + 使用或礼赠场景`。
- `subtitle` 必须明确材质特点、工艺亮点、文化寓意中的至少一项。
- `attrs` 至少包含 `工艺类别`、`核心材质`、`适用场景`，建议补充 `产地/流派`、`规格尺寸`。
- `image_keywords` 优先采用“工艺名 + 材质 + 器物名”的组合。
- 常规价格应落在 `59.00 ~ 699.00`，高于 `699` 的商品必须有收藏级、定制级、贵重材质或复杂工艺解释。

127 批次分布建议:
- 单批次不要大量集中在同一种载体，例如全部是香类或全部是摆件。
- 中低价礼赠款和中高价收藏款要有梯度，避免全是高价或全是低价。
- 每批至少覆盖 `3` 种以上工艺/材质方向。

### 8.7 AI科技(128)专属提示词约束
定位要求:
- 以服务型、方案型、交付型商品为主，例如 AI 应用开发、数字孪生、可视化、VR/3D 展示、网站/APP、备案辅导、培训咨询。
- 商品本质是“可售卖的服务套餐”，不是实体快消品，也不是只有概念没有交付的空方案。
- 价格必须与交付范围、实施复杂度、周期、适用客户规模相匹配。

优先生成维度:
- 服务维度: AI 网站、AI 知识库、客服机器人、行业智能体、数字孪生、VR 展馆、三维建模、可视化大屏、企业培训、备案辅导。
- 交付维度: 页面数量、模块数量、模型接入、部署方式、数据接入、交互能力、培训时长、售后周期。
- 客户维度: 政企展示、文旅展陈、工厂园区、学校培训、中小企业官网升级、活动营销。

禁止生成内容:
- 只有一个词或两个词的空标题，例如“代办”“培训课”“数字孪生”。
- 没有交付物、没有实施范围、没有服务对象的空泛科技商品。
- 把 AI 科技类写成实体商品、电子硬件现货、云资源倒卖或违规承诺。
- 不切实际的超高价，或者低价却宣称交付整套复杂系统。

128 标题和属性硬约束:
- 标题尽量体现 `服务类型 + 套餐层级/能力范围 + 适用场景或客户对象`。
- `subtitle` 必须说明核心交付内容、实施周期、服务收益中的至少两项。
- `attrs` 至少包含 `交付内容`、`服务周期`、`适用对象`、`部署方式`，建议补充 `售后支持`、`数据/接口范围`。
- `selling_points` 必须是可执行的交付卖点，例如“含 5 个页面”“含 1 套知识库接入”“含 30 天运维支持”。
- `image_keywords` 应优先使用“服务类型 + 场景 + 可视化/系统界面”等词，不要只写泛泛的 “AI”。

128 价格梯度建议:
- `299 ~ 5000`: 轻咨询、轻培训、基础备案辅导、基础页面类服务。
- `5000 ~ 50000`: 标准网站、三维建模、基础可视化、标准化企业服务。
- `50000 ~ 1000000`: 数字孪生、VR 展馆、复杂 APP、一体化平台、重交互大屏等企业级项目。

### 8.8 苏超纪念品(129)专属提示词约束
定位要求:
- 以江苏足球联赛氛围、城市助威文化、球迷伴手礼、低客单文创纪念品为主。
- 商品应同时具备“江苏城市元素”与“足球/助威/纪念”语义，不能只是普通旅游纪念品。
- 强调便携、好送、低门槛消费、活动现场售卖或线上周边售卖场景。

优先生成维度:
- 载体维度: 冰箱贴、钥匙扣、徽章、贴纸、水杯、帆布袋、毛绒挂件、亚克力摆件、手机支架、挂绳、小旗帜。
- 城市维度: 结合江苏 13 市地标、昵称、配色、地域符号与球迷助威语境。
- 场景维度: 助威应援、观赛打卡、旅行伴手礼、球迷交换礼、活动纪念。

禁止生成内容:
- 暗示官方授权、赛事官方指定、球队官方联名等无权证明的信息。
- 直接使用真实球员姓名、受保护 logo、俱乐部标识、赛事官方视觉资源进行命名。
- 与足球助威无明显关系的普通旅游文创或普通日用品。
- 低于分类价带的异常低价商品，或高价却没有礼盒化、套装化说明的商品。

129 标题和属性硬约束:
- 标题尽量体现 `江苏城市/苏超氛围 + 纪念品载体 + 助威/伴手礼场景`。
- `subtitle` 必须交代材质、手感、便携性、使用场景中的至少一项。
- `attrs` 至少包含 `城市主题`、`材质`、`规格尺寸`、`适用场景`。
- `image_keywords` 至少包含城市名、足球/助威语义和具体载体名。
- 常规价格应落在 `5.90 ~ 99.00`，礼盒类或组合套装可到 `299.00`，不得生成低于 `5.90` 的低价杂货。

129 批次分布建议:
- 单批次尽量覆盖 `8` 个以上城市或多个地域符号，不要只围绕 1~2 个热点城市。
- 单一载体占比建议不超过本批次的 `30%`。
- 保持“小件快消 + 中件礼赠”的结构，不要全部是毛绒或全部是冰箱贴。

### 8.9 self_check_prompt 自检要求
- 逐条检查是否符合指定 `category_id` 的定位、价格区间和禁用项。
- 逐条检查标题是否与历史商品标题重复或高度相似，如相似则直接重写。
- 逐条检查是否具备江苏本地化信息，若地域信息缺失则直接判为不合格。
- 对 `126` 检查是否真为江苏特产，是否误混全国通货、跨省商品或无地域食品。
- 对 `127` 检查是否有明确工艺、材质、技法支撑，是否只是普通摆件或普通香薰。
- 对 `128` 检查是否有明确交付内容、服务周期、适用对象，是否只是空概念标题。
- 对 `129` 检查是否同时具备城市元素和足球纪念语义，是否存在侵权风险表述。
- 逐条检查 `attrs` 是否完整、`image_keywords` 是否可用于搜图、价格是否与商品定位匹配。
- 最终只返回通过自检的 JSON 数组，不返回解释过程。

## 9. 校验与容错
### 9.1 强制校验
- 字段完整性校验: 缺核心字段即失败。
- 价格校验: 不在分类范围内则重试。
- 去重校验:
  - 与本批次 title 去重。
  - 默认与库内全表历史商品 `goods_name` 做精确去重，不仅限同分类。
  - 与库内近似标题去重(建议相似度阈值 `>=0.88` 拦截)。
  - 对标题做标准化后再比对，至少包括: 去空格、统一全半角、统一常见标点、大小写归一。
  - 近似匹配建议优先使用 `rapidfuzz.fuzz.ratio`；无第三方依赖时可回退 `difflib.SequenceMatcher.ratio`。
  - 若命中库内重复或高相似商品，则该候选商品直接丢弃并补生成，直到满足目标数量或达到重试上限。
- 地域校验: 批次内城市分布不能过于集中。

补充要求:
- 程序启动时应先拉取目标表已有商品标题，作为本次任务的库内去重基线。
- 数据库当前没有针对 `goods_name` 的唯一索引，不能依赖数据库约束防重，必须在应用层完成去重拦截。
- 默认策略为“宁可少量补生成，也不要写入明显重复的历史商品”。

### 9.2 图片校验
- URL 去重。
- HEAD/GET 可访问且状态码 `200`。
- `Content-Type` 为图片。
- 长度建议 `>1KB`。
- 主图优先过滤 `gif`，除非业务明确允许。
- 同一商品的主图和详情图 URL 不重复计入。

### 9.3 重试策略
- 千问接口: 最多 `3` 次，指数退避 `1s/2s/4s`。
- 图片接口: 最多 `3` 次，指数退避 `1s/2s/4s`。
- 单条商品最大处理次数: `2` 轮，超限入失败队列。
- 任务级总候选处理上限建议为 `count * 3`，至少 `30` 条；超过上限仍未补足数量时，任务按“部分成功”或“失败”收敛，不无限循环。

## 12. 运行方式
示例:
```bash
python3 ai_goods_pipeline/generate_goods.py \
  --category-id 126 \
  --keywords "江苏特产,盐城特产,地方礼盒" \
  --count 50 \
  --model qwen-plus \
  --write-db 1
```

可选参数:
- `--dry-run 1` 仅生成不入库
- `--export-excel 1` 导出审稿文件
- `--city-strategy balanced` 按13市均衡分布

参数语义补充:
- `--count` 表示最终通过校验并成功入库或成功导出的商品数量，不是模型一次返回的候选数量。
- 若候选商品因重复、价格越界、图片失效、字段缺失等原因被丢弃，程序应自动继续补生成，直到凑满 `count` 或达到任务级总尝试上限。
- `--dry-run 1` 下也应严格执行去重、图片校验和失败记录，只是不落库。
- `--export-excel 1` 建议导出“通过候选 + 失败原因 + 审稿备注”三类信息，便于人工复审。

## 15. 风险与应对
- 风险: 模型返回非 JSON。
  - 应对: JSON schema 校验 + 自动重试 + 修复器。
- 风险: 价格漂移不合理。
  - 应对: 分类价带硬校验，超限直接拦截。
- 风险: 图片失效。
  - 应对: URL 校验 + 失败重试 + 备用关键词。
- 风险: 密钥泄露。
  - 应对: key 轮换、最小权限、配置隔离。
