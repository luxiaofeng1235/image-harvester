# 首页（首页 - 最新.html）1:1 复刻开发文档 V2

## 1. 目标与原则

### 1.1 目标
基于 `首页 - 最新.html` 做一套从 0 开发的新首页，实现视觉与业务的 1:1 复刻。

### 1.2 核心原则
1. 不复用旧页面的画布式绝对定位结构（`#canvas + layer*`）。
2. 全新语义化 HTML 结构。
3. 全新 CSS 体系（组件化、可维护、避免样式互相覆盖）。
4. JS 单独文件、原生 JavaScript 实现（不依赖 jQuery）。
5. 业务链接、文案、图片与线上当前版本保持一致。
6. 新首页所有文件统一放在 `index_new/` 目录。

---

## 2. 本次业务范围（按页面自上而下）

1. 首屏主幻灯片区域（原 `unslider` 大图轮播）。

3. 主要项目 4 图区域（产品展示 / VR 展示 / 三维展示 / 数字化）。
4. 精品案例 6 图大卡区域（`home-jsanim-*` 这一组）。

不在本次范围：
1. 顶部 WordPress 导航模板本身改造。
2. 底部 Footer 改造。
3. 后台管理端开发。

## 3. 昨日问题复盘（必须写入重构约束）

### 3.1 已暴露问题
1. 样式优先级冲突：大量行内样式与主题样式冲突，F12 显示被划掉。
2. 区块命中错误：`Our Cases` 动画多次命中到错误 6 图（命中 `blocksit` 而非 `home-jsanim` 组）。
3. 动画时序不可控：旧结构下动画早播完、用户滚动到区域时看不到效果。
4. 首图后加载：受旧懒加载/脚本重排影响，第一张图视觉上“最后出现”。
5. 导航滚动错位：顶部注入 Banner 后，导航定位基准不稳定。
6. JS 混写问题：内联脚本过多，复制到 WP 时容易出现语法截断和执行顺序问题。

### 3.2 重构硬约束
1. 不允许在 HTML 中写业务逻辑内联脚本。
2. 不允许依赖 `layer*` ID 做业务逻辑。
3. 动画必须绑定新组件 class，不绑定旧页面随机 ID。
4. 样式禁止 `!important` 滥用，仅在主题冲突点白名单使用。
5. 导航、Banner、主体分层独立，避免相互影响定位。

## 5. 设计规范（Design Tokens）

### 5.1 基础规范
1. 设计基准宽度：`1500px`（与现页面视觉对齐）。
2. 内容容器：`max-width: 1500px; margin: 0 auto;`。
3. 字体：`"Microsoft YaHei", "HarmonyOS Sans", sans-serif`。
4. 主色：`#3c78d8`（按钮 hover / 重点交互）。
5. 正文深灰：`#5a5a5a`；浅灰边框：`#d9d9d9`。
6. 圆角：主图卡 `25px / 35px` 两档。
7. 阴影：仅用于卡片轻投影，避免重阴影。

### 5.2 间距规范（桌面）
1. 区块垂直间距：`64px / 80px` 两档。
2. 标题与内容间距：`24px`。
3. 卡片网格间距：`20px ~ 24px`。
4. “更多案例”按钮与上方内容间距：`32px`。

### 5.3 动效规范
1. 幻灯片：自动播放 + 手动切换，切换时长 `400 ~ 600ms`。
2. `home-quick-cases`：hover 仅显示标题遮罩，不做复杂动画。
3. `home-featured-cases`：入场动画采用 CSS keyframes，时间配置可调，不依赖滚动监听。
4. 支持 `prefers-reduced-motion` 降级。
5. `home-quick-cases` 点击交互固定采用 `A1` 方案（原生 Lightbox 放大预览）。

## 8. JS 实现规范（原生 JS）

### 8.1 模块职责
1. `hero-slider.js`：轮播初始化、自动播放、分页器、箭头控制。
2. `quick-cases.js`：下方 6 图 hover 文案、`A1` 原生 Lightbox、键盘与遮罩关闭、详情跳转。
3. `major-projects.js`：4 图区 hover 标题与跳转。
4. `featured-cases.js`：`Our Cases` 六图切入动画（仅绑定新 class）。
5. `about-section.js`：公司介绍区内容渲染与响应式排版。
6. `lightbox.js`：弹层容器、切图控制、焦点锁定、ESC 关闭。
7. `floating-contact-adapter.js`：兼容在线咨询插件挂载。

### 8.2 代码约束
1. 禁止使用 jQuery。
2. 禁止内联事件（`onclick` 等）。
3. 所有事件通过 `addEventListener` 绑定。
4. 所有模块暴露 `init()`，由 `home.js` 统一调度。
5. 线上即使存在默认 jQuery，也不得把新首页逻辑写成 jQuery 版本，避免后续插件冲突与时序问题。

### 8.3 主轮播固定参数（默认实施值）
1. `autoplayInterval`: `4000ms`。
2. `transitionDuration`: `500ms`。
3. `loop`: `true`（当 `slides > 1`），单图时强制 `false`。
4. `pauseOnHover`: `true`。
5. `keyboard`: `true`（`ArrowLeft/ArrowRight`）。
6. `touchSwipe`: `false`（PC 优先，避免误触）。
7. 首屏图片预热：首图立即请求，次图预加载。

### 8.4 关键尺寸与断点规范（PC）
1. 基准画布宽：`1500px`。
2. 主幻灯片高：`1080px`。
3. 幻灯片下方 6 小图区高：`213px`。
4. 主要项目四图维持两列错位比例（约 `721x428 / 719x429 / 721x464 / 719x465`）。
5. 精品案例六图维持两列三行比例（约 `710~718 x 439~443`）。
6. 断点：
   - `>= 1500px`：完全 1:1 布局。
   - `1366px ~ 1499px`：整体等比缩放到容器宽度，保持比例不换行。
   - `< 1366px`：横向滚动容器模式（本期不做移动端重排）。

### 8.5 Lightbox 可访问性规范（A11y）
1. 弹层根节点必须带 `role="dialog"` 与 `aria-modal="true"`。
2. 打开后焦点进入弹层，关闭后焦点回到触发卡片。
3. 键盘支持：`ESC` 关闭、`←/→` 切图、`Tab` 焦点循环。
4. 打开弹层时锁定 `body` 滚动，关闭后恢复。

### 8.6 “首图最后出现”治理策略（实施）
1. 不依赖旧站懒加载插件控制新首页关键图加载顺序。
2. `home-featured-cases` 第一屏可视图（至少前 2 张）设置优先请求策略。
3. 所有图片区都要有固定占位尺寸，避免图片未到时回流抖动。
4. 若运行环境仍被外部懒加载脚本接管，使用模块内降级策略强制可视区首图先展示。

### 8.7 WordPress 一次性嵌入流程（CSS/JS 上 OSS）
1. 本地构建并产出 `index_new/` 静态文件。
2. 将 `index_new/assets/css/*.css` 与 `index_new/assets/js/*.js` 同步到 OSS。
3. 在 WP 后台页面只保留：
   - 新首页 HTML 结构（容器）
   - OSS CSS 链接
   - OSS JS 链接（`defer`）
4. 资源引入顺序：`reset -> tokens -> layout -> components -> sections -> animations -> lightbox -> home.js`。
5. 后台一次性替换，不分批混用旧脚本与新脚本。
6. 发布后清理：WP 缓存 / CDN 缓存 / 浏览器缓存。

### 8.8 埋点与统计规范
1. 以下事件必须埋点：主轮播切换、6 小图点击、Lightbox 打开/关闭/切图、查看详情点击、更多案例点击。
2. 事件命名统一前缀：`home_v2_*`。
3. 示例：
   - `home_v2_hero_slide_change`
   - `home_v2_quick_case_open_lightbox`
   - `home_v2_quick_case_detail_click`
   - `home_v2_more_cases_click`

### 8.9 链接验收对照（发布必查）
1. `home-quick-cases` 6 张图链接全部返回 `200`，且与配置一致。
2. `home-major-projects` 4 张图链接与业务要求一致（VR 可按业务切到 `index-more` 时同步更新文档）。
3. `home-featured-cases` 6 张图链接全部返回 `200`，与标题一一对应。
4. “更多案例”按钮链接返回 `200`。

### 8.10 发布与回滚规范
1. OSS 文件名带版本号（示例：`home.v2.20260306.css`、`home.v2.20260306.js`）。
2. 每次发布保留上一版可回滚资源，不覆盖删除。
3. 发布窗口内先灰度验证（你本地 + 线上隐身模式），再全量。
4. 出现异常可一键回滚到上一版本号资源链接。

## 9. 1:1 复刻验收标准

### 9.1 视觉验收
1. 区块顺序、标题、文案、图片数量与线上一致。
2. 幻灯片区域高度、按钮位置与参考页一致。
3. 幻灯片下方弹层图为 6 张，hover 标题可见。
4. `Our Cases` 六图必须命中 `home-jsanim` 对应新组件，不得串区。

### 9.2 交互验收
1. 主幻灯片自动播放与手动切换正常。
2. “更多案例”按钮 hover 色正确。
3. `Our Cases` 动画节奏可配置（例如 `0/3/6/9/12/15s`）。
4. 幻灯片下 6 小图点击后必须弹出 Lightbox，且可上一张/下一张/关闭。
5. Lightbox 内“查看详情”按钮跳转链接必须与该卡片配置一致。
6. 页面刷新后，不出现“第一张永远最后出现”的视觉错乱。

### 9.3 工程验收
1. Lighthouse Performance >= 75（PC 环境）。
2. CSS/JS 无内联业务代码，文件职责清晰。
3. 不依赖旧站 `layer*` ID。
4. 能作为独立模板嵌入 WP（自定义 HTML 块或模板文件）。
