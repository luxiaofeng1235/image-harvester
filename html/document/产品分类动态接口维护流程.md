# 产品分类动态接口维护流程

## 1. 目标
- 后期不再维护本地分类 ID 映射 JSON。
- 只基于 WordPress 分类接口动态拉取：
  - 主分类（固定 3 个）
  - 子分类（按 `parent`）
  - 文章列表（按 `categories`）

## 2. 当前业务固定主分类
- `37` 加热器系列产品
- `38` 搅拌设备系列产品
- `39` 水处理系列产品

说明：产品列表页面仅使用以上 3 个主分类，其他分类忽略。

## 3. 接口流程

### 3.1 拉取主分类（固定 3 个）
```http
GET https://www.zgzonre.com/wp-json/wp/v2/categories?include=37,38,39&orderby=include&per_page=100&_fields=id,name,slug,parent,description,z_taxonomy_image_url
```

### 3.2 根据主分类拉取子分类
```http
GET https://www.zgzonre.com/wp-json/wp/v2/categories?parent={PARENT_ID}&per_page=100&_fields=id,name,slug,parent,description,z_taxonomy_image_url
```

示例：
- 加热器子分类：`parent=37`
- 搅拌设备子分类：`parent=38`
- 水处理子分类：`parent=39`（包含 `67 离子交换器`）

### 3.3 根据子分类拉取文章列表（分页）
```http
GET https://www.zgzonre.com/wp-json/wp/v2/posts?categories={SUB_CATEGORY_ID}&per_page=6&page=1&orderby=date&order=desc&_fields=id,date,title,link,featured_media,categories
```

## 4. 过滤规则
- 排除未分类：
  - `id !== 1`
  - `slug !== "uncategorized"`
  - `name !== "未分类"`

建议前端统一过滤：
```js
const categories = raw.filter(c =>
  c.id !== 1 &&
  c.slug !== 'uncategorized' &&
  c.name !== '未分类'
);
```

## 5. 维护规范
- 新增产品子分类时：
  1. 在 WP 后台将该分类挂到主分类 `37/38/39` 之一；
  2. 发布文章并勾选对应子分类；
  3. 前端无需改代码，刷新后自动出现。

- 分类展示信息来源：
  - 名称：`name`
  - 描述：`description`
  - 分类图：`z_taxonomy_image_url`

## 6. 推荐增强（可选）
- 安装 ACF 后，可给分类增加字段（如 `short_title`、`summary`、`category_image`）。
- 若需要前端通过接口读取 ACF 字段，需开启 `Show in REST API`（或使用 ACF REST 插件桥接）。

## 7. 验证清单
- 主分类接口仅返回 `37/38/39`。
- 子分类接口可返回对应主分类下所有分类（含 `67`）。
- 文章接口按子分类 ID 可正常分页返回。
- 页面中未出现“未分类”。

## 8. 插件安装记录
- `Advanced Custom Fields (ACF)`：用于给分类增加增强字段（如 `short_title`、`summary`、`category_image`）。
- `Categories Images`：用于分类图片字段，接口返回 `z_taxonomy_image_url`。
- `ACF to REST API`（可选）：当 ACF 字段无法直接出现在 `wp-json` 时安装。

建议：
- 每次插件安装、启用、停用都在本节追加一条记录（日期 + 插件名 + 用途）。

---
维护原则：**后台维护分类与文章，前端走动态接口，不再手动维护子分类 ID 映射。**

## 9. 分类页动态集成方案（当前落地版）

### 9.1 当前落地原则
- `name`：直接使用分类名称。
- `slug`：直接作为分类唯一标识使用，可替代旧 JSON 中的 `key`。
- `description`：直接作为分类介绍使用。
- `z_taxonomy_image_url`：直接作为分类图片使用。
- `shortTitle`：仅少量分类需要，暂不走接口，使用本地小配置映射。

### 9.2 当前无需再维护的大 JSON
- 旧文件：`home-category-content-config-v1.1.json`
- 旧文件中的大量字段（如 `paragraphs`、`featuresTitle`、`features`）在当前分类页 UI 中未使用，不再作为首要维护来源。
- 当前分类页不再依赖“全量静态分类文案 JSON”驱动分类主数据。

### 9.3 当前仍保留的本地配置
- 文件：`home-category-runtime-config-v1.2.json`
- 作用：
  - 固定 3 个主分类入口；
  - 固定主分类下子分类排序；
  - 维护少量短标题映射。

#### 9.3.1 主分类固定集合
- `37` 加热器系列产品
- `38` 搅拌设备系列产品
- `39` 水处理系列产品

#### 9.3.2 当前 shortTitle 本地映射
- `42`：环保、节能、低压
- `43`：升温快、效率高
- `44`：加热均匀、性能好
- `45`：适应性强、种类多
- `46`：热效性高、散热快

说明：
- 目前仅加热器下这 5 个子分类使用短标题。
- 其他子分类未配置时，前端不显示短标题即可。

### 9.4 当前分类页数据来源
- 主分类：
  - 通过 `include=37,38,39` 动态读取。
- 子分类：
  - 通过 `parent=37/38/39` 动态读取。
- 产品列表：
  - 通过 `posts?categories={子分类ID}` 动态读取。
- 分类展示：
  - 标题：`name`
  - 别名：`slug`
  - 描述：`description`
  - 图片：`z_taxonomy_image_url`

### 9.5 后期维护规则（当前最简版）
- 新增子分类时：
  1. 在 WP 后台将子分类挂到 `37/38/39` 之一；
  2. 维护分类描述与分类图片；
  3. 发布文章并勾选对应子分类；
  4. 前端自动读取，无需改分类结构代码。

- 新增子分类若需要短标题时：
  1. 在 `home-category-runtime-config-v1.2.json` 的 `shortTitleMap` 中补一条；
  2. 若不需要短标题，则无需改本地配置。

- 新增主分类时：
  1. 需要在 `home-category-runtime-config-v1.2.json` 中新增主分类配置；
  2. 包括 `type`、`parentId`、`label`、`displayName`、`childCategoryIds`。

### 9.9 当前方案结论
- 分类页主数据已经基本动态化。
- 后期一般只维护后台分类数据。
- 仅以下两种情况需要维护本地配置：
  - 新增主分类；
  - 新增子分类且该子分类需要短标题。
